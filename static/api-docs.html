Overview

Flow2API exposes Google Flow (Veo and Gemini image models) through two request formats. Pick whichever your client already speaks; both reach the same generation pipeline.

OpenAI-compatible

Chat Completions shape. Works with the OpenAI SDKs by changing base_url and api_key.

POST /v1/chat/completions

Native Gemini

generateContent shape, for clients built against the Google AI API.

POST /v1beta/models/{model}:generateContent

Generation is slow. Images usually take tens of seconds and videos several minutes. Default server timeouts are 300s for images and 1500s for videos. Prefer stream: true so the connection stays active and you receive progress updates.

Authentication

Every endpoint below needs the API key from System Settings. Any of these three forms is accepted.

Form Example Typical use
Authorization Authorization: Bearer <api_key> OpenAI SDKs and most HTTP clients
x-goog-api-key x-goog-api-key: <api_key> Google AI SDKs
key ?key=<api_key> Query string, when headers are hard to set

A missing or wrong key returns 401 with {"detail": "Invalid API key"}. The admin session cookie does not authorize these endpoints; the API key does.

Quickstart

Generate one landscape image. Replace the key with your own; the base URL is prefilled from this page.

Models

                    
There are two ways to name a model. Both are valid; pick one and stay consistent.

                    

                        

                            
1. Explicit model id

                            
The id already encodes aspect ratio and duration, so no extra parameters are needed. This is the most predictable option.

                            gemini-3.1-flash-image-landscape
                            veo-3.1-fast-8s-landscape
                        

                        

                            
2. Alias plus generationConfig

                            
Send a short alias and let the server resolve the concrete model from aspectRatio and imageSize. Useful for gateways that only forward a generic model name.

                            gemini-3.1-flash-image + aspectRatio: "16:9" → gemini-3.1-flash-image-landscape
                        

                    

                    
Call /v1/models for the full catalog and /v1/models/aliases for the alias list. Accepted aspectRatio values:

                    

                        16:9 → landscape
                        9:16 → portrait
                        1:1 → square
                        4:3 → four-three
                        3:4 → three-four
                    

                    
imageSize accepts 2k and 4k. Videos only resolve to landscape or portrait; other ratios fall back to the closest of the two.

                


                
                

                    
Image generation

                    
Text to image uses a plain string prompt. Image to image adds up to 5 reference images as image_url parts.

                    

                        
                        

                    

                    
Reference images accept a data: URL (data:image/png;base64,...) or a public http(s) URL. Data URLs are the safest, since the server does not need outbound access to fetch them.

Extending a video

                        
Pick an extend model (for example veo-3.1-fast-extend-8s-landscape) and pass the previous media id as an image_url with the extend:// scheme. The id comes from the data-media-id attribute of the earlier video result.

                        {"type": "image_url", "image_url": {"url": "extend://<media_id>"}}
                    

                


                
                

                    
Responses

                    
Results arrive as Markdown or HTML inside the assistant message, not as a dedicated media field. Parse the URL out of the content.

                    

                        

                            
Image result

                            ![Generated Image](https://host/tmp/abc.png)
                        

                        

                            
Video result

                            <video src='https://host/tmp/abc.mp4' controls></video>
                        

                    

                    
Streaming (stream: true)

                    
Server-sent events. Progress arrives in delta.reasoning_content and the final result in delta.content with finish_reason: stop, followed by data: [DONE].

                    

                        
                        

                    

                    
Non-streaming

                    
A single chat.completion object once generation finishes. Gemini endpoints return candidates[].content.parts instead, with inlineData for images and fileData for videos.

                    

                        
                        

                    

                


                
                

                    
Errors

                    

                        

                            
                                

                                    Status
                                    Meaning
                                    What to do
                                

                            
                            
                                

                                    400
                                    Empty prompt, or neither messages nor contents
                                    Fix the request body
                                

                                

                                    401
                                    Missing or invalid API key
                                    Check the key in System Settings
                                

                                

                                    404
                                    Unknown model id
                                    List models and use an exact id
                                

                                

                                    500
                                    Generation failed upstream, or no usable token
                                    Open Request Logs for the detailed reason
                                

                            
                        

                    

                    
OpenAI-shaped errors look like this; the Gemini endpoints return error.code and error.status instead.

                    
{
  "error": {
    "message": "No available Token for image generation. ...",
    "type": "server_error",
    "code": "generation_failed",
    "status_code": 500
  }
}

                    
During streaming, an error can also arrive as an SSE event carrying the same error object, so check each chunk for an error key.

                


                
                

                    
Notes for agents

                    
    
                        
  • Set a long read timeout. Images take tens of seconds, videos several minutes; the server allows up to 300s and 1500s respectively.
    • 
                        
  • Prefer stream: true. Non-streaming requests hold one connection open with no feedback until the very end.
    • 
                        
  • Extract the result URL with a regex over the content: !\[.*?\]\((.*?)\) for images and <video src='([^']+)' for videos.
    • 
                        
  • Download the media promptly. Cached files live under /tmp/ and are deleted once the cache timeout expires (2 hours by default).
    • 
                        
  • Send one generation at a time per token unless you know the concurrency limit; parallel requests compete for the same Google accounts.
    • 
                        
  • Pick explicit model ids over aliases when you need an exact aspect ratio or duration; aliases depend on generationConfig being forwarded intact.
    • 
                        
  • Treat the prompt as the only instruction channel. systemInstruction is merged into the prompt for media models and may be dropped when it looks like a chat preamble.
    • 
                        
  • Use the Model Tester tab to confirm a model and prompt interactively before wiring it into code.
    •
